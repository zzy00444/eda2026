# 第十阶段优化记录

更新：2026-10-21。进行中，尚无通过联合门槛的新发布版。按[计划](第十阶段精度与综合分联合优化计划.md)仅进行本地 Docker 测试，保留第八、第九阶段所有发布产物。

## 已完成诊断

第九阶段 64 树相对第八阶段的验证增益为约 0.419 分，分散在多数请求。只对基础预测低于 4000 ps 的约 74% 请求启用教师，也仅达到约 98.004，无法靠简单的稀疏开关解决速度问题。基础预测与周期架构包络的差值、源端口、目标端口是残差的主要有效特征。

强制 Net 落点进入墙体的请求占验证集 293/50000；第八阶段该组准确度为 72.147，第九阶段高精度版为 91.606。单独训练的墙内模型达到约 96.24，适合仅对这一小组启用较多树。

## 紧凑模型试验

所有新拟合参数使用既定的 719583 行源坐标排除训练集；墙内子模型使用其中 4233 行。继承的基础模型和校准并非全系统源坐标隔离。固定历史验证集被反复用于选择，不能称为盲测。

| 试验 | 验证准确度 | 结论 |
| --- | ---: | --- |
| 9 张加性校正表，35377 单元 | 97.882470 | 仅查表不足 |
| 扩大到 18 项，302167 单元 | 97.859817 | 增加交互项反而下降 |
| 用第九阶段高精度输出蒸馏 18 项 | 97.884733 | 蒸馏仍不足 |
| 9 表 + 一棵 127 叶普通树 + 64 棵墙内树 | 98.015680 | 测试回归 98.032740，精度达标，速度待优化 |
| 对普通请求再前向选择 8 张表 | 普通组 97.999316 | 全系统加墙内模型仍约 97.9895，未达门槛 |

脚本：`displacement_compact.py`、`displacement_lut_greedy.py`、`displacement_hybrid.py` 和 `displacement_hybrid_export.py`。模型与数组在 `solution/build/displacement`，不入 Git。最初批处理候选错误地省略墙内模型使用的 `lut_minus_base`，逐条检查发现 2610 处差异；已修复导出器，旧 `stage10_hybrid1` 仅作为诊断证据，禁止发布。

## Docker 速度与实现

第一版混合候选两轮平均 4.650429 s/10M，同批第八阶段 2.243460 s。普通请求只构造必要特征，并提前预取包络表后，`stage10_hybrid_quick` 达到 3.121328 s，同批第八阶段 1.975085 s。百万条输出与 Python 参考零差异。仍未达到联合综合分要求，因此没有切换默认版。

运行波动明显：不同轮第八阶段出现 1.35～2.94 s，不能跨批拼接有利的时间。以上仅两轮筛选，最终必须同批五轮；`stage10_quick_screen_benchmark.json` 等均为筛选证据。继续试验定点查表、等价包络算术及快速取整，所有实现变化均需重新验证。

## 架构生成距离重拟合

只读检查外部工程现有 `build/all_C_<source>.bin`，208 个源表尺寸均为 153391680 字节，架构文本 SHA 与仓库冻结资产一致。没有修改外部工程。`displacement_generated_refit.py` 用不相交的生成位移抽样评估系数重拟合；12 组加权/正则配置中，最好仅提高生成距离代理准确度约 0.000623。没有进行全量重拟合、没有读取公开标签进行此项选择，暂不投入更大成本。详见 `stage10_generated_refit.json`。

后续尝试改变基础表示；如联合门槛最终未通过，明确保留现有发布版本。

## 局部生成残差（进行中）

定点 LUT 的验证/测试准确度为 98.015685/98.032659，但两轮 Docker 平均 3.023850 s/10M，同批第八阶段 1.981968 s，仍未过综合分门槛。单轮消融中，第八阶段 2.004781 s，仅包络 2.476914 s，仅包络加 LUT 2.578573 s，完整方案 2.948659 s。全体请求的包络访问本身已很贵，故转向只对局部位移增加内积。

只读原始生成距离、固定当前选择分支的诊断参考可达验证 99.146944；仅替换距离小于 50 的请求也能达到 98.097006。它是可用信息的诊断，不是已部署算法或速度证据。

`displacement_local_train.py` 已完成 `dx=-24..24,dy=-120..120` 的生成残差随机 SVD，保存 160 维前缀。目标是原始生成距离减原始架构低秩模型，不使用公开延迟标签；端口频率权重仅使用既定 719583 行训练几何。外部 208 个原料文件只读并记录尺寸/mtime，训练结束删除约 2.83 GB 临时矩阵。训练记录见 `stage10_local_weighted_training.json`。

`displacement_local_screen.py` 在旧选择分支上筛选，验证准确度：8 位 64/96/128/160 维分别为 97.830393/97.873976/97.909075/97.936301。16 位最高 97.936607，量化损失很小。尚未读测试标签作本轮配置选择；以上不是实际双候选部署结果。

新增局部资产格式、导出器和可选运行时，构建用 `--local-file`。局部内积单独四舍五入，加入原始整数内积预测，再执行两分支最小值、几何项及历史校准。局部残差是在原始架构 U/M 上训练后加到第八阶段 refit 上，并未取消历史 refit，因此最终收益必须以实际部署核对为准。

96 维实际部署基线上，另训不依赖包络的墙内模型（4233 行），只对约 0.6% 的请求调用；64 树候选 `stage10_local96w64` 验证/测试准确度 98.015370/98.021603，新增参数源坐标留出 98.041809。独立 Python 重建原/压缩墙两分支、float32 FMA 内积、校准和墙内树，百万行与 C++ 零差异；第八阶段参考也零差异，见 `stage10_local96w64_reference.json`。

第一版两轮筛选 CPU 为 2.644621 s/10M，第八阶段同批 2.327089 s，接近综合分边界。随后把墙内 gate 提前到解析阶段，仅在命中时保存额外坐标，普通请求不再调用墙内函数；新 ELF 仍输出相同百万行 SHA，正在重新验收。旧两轮报告只证明旧 ELF，不证明当前版本。

额外检查 160 维、160 棵稀疏墙内树作为高精度备选，冻结后的 Python 墙内参考验证/测试为 98.079389/98.074532，位置留出 98.095581。与第九阶段最高精度相比测试仅提高约 0.0055，不能据此宣称隐藏集显著提高。两种配置均待完成最终五轮测速、完整新 ELF 参考核对和独立 ZIP 验收；默认及所有已发布备份尚未切换。
