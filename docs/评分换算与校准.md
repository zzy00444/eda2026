# 评分换算与校准

本文件规定分数、时间与校准的唯一口径。任何候选的估分必须能按本文件复算。

## 1. 评分公式

```text
total = 0.8 * acc + 0.15 * time_score + 0.05 * consistency
time_score = max(0, 1 - avg_cpu_seconds / 1800) * 100
```

- `acc`：逐条 `100 * (1 - tanh(4 * |pred - truth| / truth))` 的均值；`truth = 0` 时仅当 `pred = 0` 得满分。
- `avg_cpu_seconds`：官方 5 次运行 CPU 时间（`user + sys`）的均值，包含读文件、建表和写文件。
- `consistency`：5 次输出逐字节比较，全同 = 100，否则 = 0（且 acc 取 5 次均值）。
- 任一单次 > 3600 s 或内存 > 2 GB：作品无效，0 分。

反解（验收用）。先把一致性满分的情形化简，两个等价形式都必须能对上：

```text
total = 0.8*acc + 0.15*100*(1 - cpu/1800) + 5
      = 0.8*acc + 20 - cpu/120            # 15/1800 = 1/120

required_acc(total, cpu) = (total - 5 - 15*(1 - cpu/1800)) / 0.8
                         = 1.25*total - 25 + cpu/96
```

校验点（`tools/score.py --self-test` 逐点断言）：`acc=100, cpu=178 s` ⇒
`total = 80 + 20 - 178/120 = 98.5167`。

| 官方 1B CPU | time_score | total=98 需 acc | total=98.5 需 acc | total=99 需 acc |
|---:|---:|---:|---:|---:|
| 90 s | 95.00 | 98.44 | 99.06 | 99.69 |
| 110 s | 93.89 | 98.65 | 99.27 | 99.90 |
| 120 s | 93.33 | 98.75 | 99.38 | 100.00 |
| 130 s | 92.78 | 98.85 | 99.48 | — |
| 160 s | 91.11 | 99.17 | 99.79 | — |
| 178 s（实测地面） | 90.11 | 99.35 | 99.98 | — |
| 242 s（旧路线实测） | 86.56 | 100.02 | — | — |

## 2. 本机测速口径

- 环境：Windows + WSL2 `Ubuntu-20.04` + Docker Desktop；镜像 `fpga-ziguang:latest`，平台 `linux/amd64`。
- 约束：`docker run --rm --cpus=1 --memory=2000000000 --memory-swap=2000000000`，以当前 WSL UID/GID 运行，工作目录绑定 `/work`。
- 计时：容器内 `user + sys`（bash `TIMEFORMAT='wall=%R user=%U sys=%S'`）。
- 输入：公开 1M 请求重复 100 次 = 100M 行；5 轮正反交替；每轮校验输出哈希一致。
- 外推：`local_1B = mean(100M cpu) * 10`。
- 文件系统：基准必须放在 WSL 原生目录（`/mnt/c` 的 9p 会污染 CPU 统计，实测纯拷贝 1M 行 wall 0.69 s vs CPU 0.067 s）。

## 3. 官方/本机比例

历史只有两个口径，**不可混用**：

| 来源 | 比例 `official / local` | 备注 |
|---|---:|---|
| pango 路线（`g144q8_l192_half_i8`） | 1.168627 | 官方 1B 实测 241.73 / 242.57 s，均值 242.15 s；本机外推 207.21 s |
| solution 路线（`stage11_balancedw64`） | 1.401789 | 官方 1B 实测 287.12 / 274.88 s，均值 281.0 s；本机外推 200.46 s |

规则：

1. 新候选若改变 I/O、分支或访存模式，必须**重新校准**，不得沿用旧比例；
2. 校准优先用 100M 榜单（5 次/日）：官方 100M CPU `× 10` 作为官方 1B 估计；
3. 1B 榜单（2 次/日）只做终验，不做探索；
4. 每次提交记录：候选名、ELF SHA-256、ZIP SHA-256、官方 accuracy、官方 CPU、官方 total、日期。

## 5. 记分纪律

- acc 与 CPU 必须来自**同一个 ELF、同一资产、同一批基准**；
- 不允许把 A 版本的 acc 与 B 版本的 CPU 拼成"预计分"；
- 公开集、真值留出集、榜单、官方实测必须分栏列，不得合并口径；
- 提交到榜单的准确性只作校准，**最终以全空间真值抽样为主判据**（榜单是 2M 循环，终评是 1B 互异）。
