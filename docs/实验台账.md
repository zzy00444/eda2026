## 3. S2 误差分解（精确标签，240k 行，12 源端口）

## 4. S3 结构度量：表示形态的能力上限（全部用精确场测量）

| 表示 | 规模 | 真值留出 mae | acc（真值抽样） | 结论 |
|---|---|---:|---:|---|
| 斜率 + 余数（4 象限 × 120 余数） | — | 26–30 ps | — | 位移维不可用斜率+余数表达 |
| **全局共享 pair 基**, rank 128 | 15.3 MB | 10.15 ps | 97.82 | 与旧路线一致 |
| **全局共享 pair 基**, rank 256 | 30.7 MB | 9.42 ps | **97.96** | **撞墙：秩加不上去** |
| Tucker 64×64（共享端口因子 + 逐 cell 核） | 246 MB | 7.22 ps | 98.44 | 体积超预算 |
| **逐 cell 低秩**, rank 32 | 956 MB（不可行） | **2.16 ps** | **99.43** | **信息在，容量不够** |
| 逐 cell 低秩, rank 16 | 478 MB | 3.95 ps | 98.98 | 同上 |
| 逐 cell 低秩, rank 8 | 239 MB | 6.49 ps | 98.30 | 同上 |
| 逐 cluster 基（dx mod 10, dy mod 12）, rank 8 | 58 MB | 16.15 ps | 95.73 | 样本不足，暂判不可行 |

**核心发现**：延时矩阵在每个位移 cell 上只有 rank≈16–32，但**端口对的模式随位移旋转**
（全局基 rank 256 仍停在 ~9.4 ps ≈ 97.96）。旧路线的 98.2 上限就是这把"旋转墙"。
因此 S3 的唯一出路是**cell 自适应分解**（逐 cell 基的紧凑参数化、结构化端口张量、
或 lane 级 H 矩阵），而不是更高的全局秩或更大的位移表。
