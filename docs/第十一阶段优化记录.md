## 基线与校准消融

`displacement_match.py` 用独立 Python 的 float32 FMA 和真实双分支重建，不是固定旧分支代理；墙内最终输出固定为第十阶段默认以隔离普通组。原配置重建与百万行已部署预测零差异。新校准仅用排除留出位置后的普通训练行。

| --- | --- | ---: | ---: |
| 当前 refit M | 旧校准 | 98.015370 | 98.041809 |
| 当前 refit M | 重拟合校准 | 98.018361 | 98.042726 |

取消校准也没有改善。结论是匹配差异存在，但收益只有约 0.003～0.005，且位置留出不支持改变局部 M；本轮暂保留旧校准，新增压缩直接拟合 refit 基线的残差。未读取测试标签选消融配置，详见 `stage11_match.json`。

## 分区候选训练中

首批互斥区域：内区 `|dx|≤16, |dy|≤48`；中区 `|dx|≤32, |dy|≤160` 扣除内区；外区 `|dx|≤64, |dy|≤320` 扣除中区。各区独立秩和量化，运行时每个候选只执行命中区域的一次局部内积。

相对误差权重首先采用生成距离逆平方按位移聚合后的可分离代理，再乘训练端口频率；没有声称这是逐元素相对误差的精确最优解。生成数据及权重均不使用公开 delay 标签。新格式 `PGLOC002` 保留 `PGLOC001` 读取兼容，独立参考也同步支持分区。

## 粗分区与加权细化的负结果

三粗分区的固定旧分支代理约 98.11，未达目标。外区 40 维覆盖约 41.8% 验证请求，却只增加整体约 0.054，在线性价比有限。内区 96 维进行了 10 次逐元素逆平方加权细化，生成加权平方损失从 374.165 降至 354.089（约 5.4%），但验证代理提升只有约 0.0013，因此不把训练目标下降当成最终准确度收益。

该细化训练完成并保存因子后，Windows 的最后一块 memmap 视图阻止清理临时文件。已修正显式关闭句柄，原模型不重训；训练报告从捕获的 stdout 重建并显式标注恢复经过，临时文件已清理。没有用缺失证据冒充通过完整验收。

另检验直接压缩生成距离，在覆盖区跳过原 128 维基础内积。粗内区 160 维 / 中区 128 维的 UInt16 系数代理约 98.086，UInt8 约 98.056；仍不足目标。小范围无损密集表的抽样压缩预算也不合适（`|dx|≤8, |dy|≤24` 预计约 23 MB，尚未计基础包与其他区域），未引入部署。

## 细分位移区域

已完成 12 个互斥区域的两种表示训练：x 边界 `[-32,-8,9,33]`，y 边界 `[-160,-48,0,49,161]`，左闭右开。每区分别训练残差与直接距离，最高秩 96，按生成相对误差行/列边际加权。只训练并存储 23,321 个训练几何中出现的端口组合，其余组合保留旧基线；未用验证/测试标签选端口。验证请求中约 0.136% 的端口组合未在训练几何出现。

训练共享一次生成距离缓存，171 秒完成 24 个模型，临时缓存已删除。新混合格式 `PGLOC005` 在各区域记录独立表示、秩和稀疏端口映射；旧格式保持可读。接下来用 valid 在包体预算及内积成本代理下选完整配置，再做真实双分支与同批 Docker 测速。测试标签尚未用于选型。

测速工具新增 `--repeat`：默认仍为 10M，`--repeat 100` 为 100M；输出记录实际行数、重复次数、正确的 1B 外推和归一化 10M 时间，并校验重复输出 SHA。发布器按实际行数校验，不混淆两种规模。

## 真实双分支与包体收敛

三套配置已冻结后运行 C++ 并独立核对 valid，均零差异。固定旧墙内输出时，`stage11_fast` / `stage11_balanced` / `stage11_accurate` 分别为 98.076300 / 98.200953 / 98.265345。前两者 ZIP 94,948,813 / 98,058,966 B，最后一套 103,509,440 B 超限，不能发布为提交包；其具名 ELF、因子及诊断仍保留。

采用不改变数值的 V 行间 lag-12 差分、秩优先排列和双字节平面，再用 XZ 压缩。普通转置、BZip2 及更高 XZ 级别未改善到足够预算，采用实测更小的 XZ preset 6。封装工具逐字节核对压缩前后资产；运行时调用官方 Docker 已有 `liblzma.so.5` 解压，恢复 int16 矩阵。独立 Python 同样恢复矩阵；真实 valid 预测核对零差异。

为满足实际 100 MB 限制，将精度配置中的 `10`、`13` 两区从 80 维降至 64，得到 `stage11_compact`：匹配 160 棵墙内树后的验证准确度 98.258566，尚待冻结后的测试回归与完整验收。局部资产 28,848,548 B，XZ 18,899,584 B；无墙内树 ZIP 99,708,624 B。局部压缩逐字节回环通过，编码本身无精度损失。

三套最终配置冻结为 `stage11_fastw64`、`stage11_balancedw64` 和 `stage11_compactw160`。现在才读取测试回归，并进行百万行/保留查询参考、独立 ZIP 和五轮同批长输入测速；发布决定待实测后作出。

三者已完成百万行独立 Python/C++ 零差异，重建第八阶段也零差异；56 条官方/保留查询一致，11 项接口、11 项边界以及空目录 ZIP 独立运行通过。最终测试准确度依次为 98.073604 / 98.192013 / 98.247955，精度版 valid 为 98.258566，但 test 比 98.25 低约 0.002045，严格目标尚未完全达到。精度版 ZIP 99,807,086 B，48 条保留位置准确度 96.329763。

超限诊断包改名 `stage11_accurate_oversize_submission.zip`，具名实验 ELF 与因子保留，避免和合法提交包混淆。默认暂未切换，接下来仅做五轮 100M 同批测时；不再根据已查看的 test 调整模型。
