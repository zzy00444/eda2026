## 1. 目标与成功判据

评分公式（一致性满分时）：

```text
total = 0.8 * acc + 0.15 * time_score + 5
time_score = 100 * max(0, 1 - official_1B_cpu_seconds / 1800)
```

反解出"达到某总分所需 acc"：

| 官方 1B CPU | time_score | 达到 98 需 acc | 达到 98.5 需 acc | 达到 99 需 acc |
|---:|---:|---:|---:|---:|
| 90 s | 95.0 | 98.44 | 99.06 | 99.69 |
| 110 s | 93.9 | 98.65 | 99.28 | 99.90 |
| 130 s | 92.8 | 98.85 | 99.48 | 不可达（需 >100） |
| 160 s | 91.1 | 99.17 | 99.79 | 不可达 |

**硬指标（冻结候选必须同时满足）**

1. 官方 1B 综合分 ≥ 98.5，冲刺 99.0；
2. 等效组合：`acc ≥ 99.3` 且 `官方 1B CPU ≤ 110–130 s`；
3. 五次运行输出逐字节一致（consistency = 100）；
4. ZIP ≤ 100 MB、运行 RSS ≤ 2 GB、单线程、单次运行 < 1 h。

**中间门槛（阶段门槛，见 §5）**

- 真值留出集 `mae ≤ 5 ps`（对应 acc ≈ 99.0）；
- 本机 1B 等效 CPU ≤ 85 s（100M ≤ 8.5 s）；
- 模型（编译进 ELF 的整数参数）≤ 40 MB。

## 2. 已核实的事实（本路线的事实基础）

### 2.1 真值语义已完全确定

延时 = `Σ SRB 内部 arc 延时 + Σ 跨越 gap line 的代价 + 可穿越 block 代价`；net 本身零基础延时（Q&A A1/A2）。

- 官方 8 条 check 路径的 golden 与精确 Dijkstra 全等：`973 / 843 / 786 / 997 / 929 / 562 / 692 / 661`（历史记录 `pango_delay_handover_v3/results/exact8.txt`）。
- 本轮用一份独立编写的窗口化精确 DP（不引用旧工程代码）复现 6/6 条 check 行（另 2 条超出窗口），且在其覆盖范围内 973 条公开样本里 849 条逐 ps 全等；未全等者全部是"真值 > 模型"，可由"源端 net 超调往返多跨一次线路"解释。

结论：**残差是确定性结构，不是随机噪声**，因此可以被"算出来"而不是"拟合出来"。

### 2.2 旧路线的误差是全局均匀的表示误差

在本机公开 1M 上重跑旧候选 `estimate_stage11_balancedw64`（仅作基准，不作代码基础）：

| 指标 | 值 |
|---|---:|
| accuracy | 98.2116 |
| mae | 10.53 ps |
| abs err p50 / p90 / p99 | 6 / 22 / 83 ps |
| 相对误差 p50 / p90 / p99 | 0.233% / 0.955% / 3.81% |

按真实延时分桶（同一次运行）：

| 延时桶 | 行数 | acc | mae | 对总损失的贡献 |
|---|---:|---:|---:|---:|
| [0,300) | 524 | 92.74 | 5.54 | 0.004 |
| [300,600) | 11,769 | 94.85 | 6.43 | 0.061 |
| [600,1000) | 48,379 | 95.82 | 8.58 | 0.202 |
| [1000,1500) | 96,770 | 96.99 | 9.56 | 0.292 |
| [1500,2000) | 121,363 | 97.66 | 10.28 | 0.285 |
| [2000,3000) | 257,037 | 98.20 | 11.11 | 0.462 |
| [3000,4000) | 205,038 | 98.75 | 10.80 | 0.256 |
| [4000,6000) | 225,895 | 99.09 | 10.83 | 0.205 |
| [6000,10000) | 33,225 | 99.35 | 10.52 | 0.022 |

要点：**损失按行数摊开、各桶 mae 近似恒定（5.5–11 ps）**。修任何单一局部（墙、短延时、某端口族）都只能挪动零点几。要跨过 98，必须把全区间误差整体减半。

在**精确标签**上复测（S2：240k 行、12 个源端口，目标位置/端口均匀）：
`acc 97.9893 / mae 9.27 ps / p50 7 / p90 20 / p99 47`。分组结果与直觉相反——
**跨墙 98.65 > 非跨墙 97.74，墙廊 98.30 > 非墙廊 97.97，近边 98.70 > 非近边 97.75**，
即缺陷行反而更准。**缺陷不是主要误差源，误差是全域均匀的表示误差**；
这也解释了为什么两条旧路线在墙/边界修正上投入只换到 0.0x 点。

### 2.3 公开集覆盖严重不足

| 项目 | 公开 1M | 隐藏 1B |
|---|---|---|
| From 端口 | 113 / 208 种 | 架构文件全部源端口 |
| To 端口 | 256 / 288 种 | 架构文件全部 output 端口 |
| 位置 | 无 (x<16, y<100) 区域；`|dx|+|dy| ≤ 800` | 全阵列、全位移 |
| 重复 | — | 原则上互不相同（Q&A A13/A20） |

结论：**用公开 1M 选型必然过拟合**；必须用架构推导的全空间真值。

### 2.4 位置效应是离散路线翻转

- `Δx > 0` 时延时严格平移不变（旧工程扫 120 列实测 std ≤ 1.8 ps）；
- `Δx ≤ 0` 出现离散台阶，幅度精确等于 `2 × vline 代价`（源端 net 先向右跨一格，再折回再跨一次）；
- 墙廊相邻列另有 132–248 ps 跳变。

结论：位置依赖只能通过"判断走哪条路"消除，不能靠连续修正项拟合。

### 2.5 精确性的摊销结构（本路线的地基）

| 项目 | 实测/推算 |
|---|---|
| 逐行精确求解 | 0.04 s（短）～1.4 s（长）；比 1B 预算慢 2.2×10⁴～7.8×10⁵ 倍 |
| 只对 0.01% 行精确 | 100k × 0.04 s ≈ 4000 s，仍超预算 |
| 按（源位置, 源端口）整场算一次 | 实测 **3.05 s CPU / 34.7 MB / 26.75M pops**（`SRB_40_275/ZSNB[4]`，全 288 目标）；40 个源位置约 2 min，208 个约 11 min |

结论：**精确必须离线摊销在源端口上，不能花在每一行上**。这条非对称性是本路线与"逐行精确 A*"方案的根本区别。

### 2.6 I/O 地板已实测

最小 C 程序（只读入 + 复制并追加 `,100`）在本机容器内处理公开 1M 行：`user + sys = 0.067 s`（≈67 ns/行），wall 0.69 s（`/mnt/c` 慢盘）。1B 行约 41 GB 入 + 46 GB 出，CPU 地板约 50–65 s（官方原生盘更快）。**算力预算足够，瓶颈是模型表示。**

### 2.7 榜单 ≠ 终评

- 打榜 1B 页面：2M 对数据循环扩充至 1B（每条重复约 500 次），2 次/日；
- 打榜 100M 页面：2M 对循环扩充至 100M，5 次/日，只按 accuracy 排序但显示 CPU；
- **最终评测：1B 条互不相同的数据**（Q&A A13/A20），覆盖全部端口与位置。

结论：任何依赖"请求重复"的手段（缓存、逐行精确 + 去重）都只能刷榜，终评会崩。

### 2.8 为什么不做"规则化下界 + 惰性精确 A* + 残差校正"

| 判断 | 依据 |
|---|---|
| 紧致下界已到位 | 线路望远镜恒等式 + 292 墙 + min-plus 度量即最紧解析下界；但评分用估计值，下界本身公开集 acc 仅 91.3 |
| 惰性 A* 会退化为几乎全量精确 | acc 99 只容 ~7.5 ps / 3000 ps；近似差距 ~10 ps ⇒ 约六成行越界 ⇒ 6 亿次精确求解 |
| 预算直接否决 | 0.01% 行 × 0.04 s 已 4000 s；即使 20× 加速仍超 2 个数量级 |
| 榜单会骗人 | 2M 循环可缓存刷榜，1B 互异终评必崩；且 2M × 0.04 s ≈ 22 h，连榜单都撑不住 |
| 残差校正已封顶 | 本机 98.19 / 官方 96.44；位置盲下限实测 31.8 ps ⇒ acc ≈ 97.6 |
| 采纳的部分 | A* 作为**离线**真值/对抗样本工具；近场 1–2 hop 的精确枚举（§3.2 M3）；任何线上精确通道必须过预算闸门（§3.5） |

## 3. 技术路线：精确结构复现（Exact-Structure Reconstruction）

一句话：**先用离线真值工厂拿到全空间精确标签，再把真值写成"精确位移度量 + 精确缺陷代数"的 O(1) 整数式；线上不做搜索、不做低秩截断、不做位置盲残差。**

与两条旧路线的区别：

| 维度 | 旧路线 | 本路线 |
|---|---|---|
| 监督来源 | 公开 1M 标签 | 分层源位置 × 288 目标 × 60,200 位置的全空间真值 |
| 误差处理 | 当作可学习残差（树/低秩/校准） | 拆成确定性缺陷项 + 唯一未知的 min-plus 暂态 |
| 表示 | 大表 + 低秩（受 ZIP/CPU 挤压） | min-of-modes 暂态式 + 小表（常驻 L2/L3），靠预取换速度 |
| 位置 | 位置盲或粗校准 | 用离散台阶/墙/边界公式精确表达 |

### 3.1 真值工厂（S1）

- `tools/oracle.cpp`：Dial 算法全芯片精确最短路，直接由 5 个 JSON 导出的 `arch.txt` 建图（约 250 行，新写，不复制旧工程）。
- 校验（S0 门槛）：
  1. 8/8 check 行 golden 全等；
  2. 分层抽样公开行（含跨墙、门前、block0 邻域、四边 12 格、长位移）oracle = golden 全等；
  3. 越界 / 断线 / block 落点平移 / 自环 / 反向不可达 的专项用例。
- `dump` 模式：从 **(源 SRB 坐标, 源端口)** 出发做一次全芯片最短路，导出 `uint16[60200][288]` 距离场（34.7 MB / 次，3.05 s CPU / 次，实测）。
- **dump 集合的设计**（不是"208 个源端口"那么简单）：延时依赖源位置、目标位置与两端端口；内部区域对位移严格平移不变，所以**一个内部源位置的一次 dump 就给出全部位移上的精确度量**（60,200×288 个标签）。缺陷相关的位置依赖用**分层源位置**覆盖：内部相位（x mod 10 / y mod 100 各类）、每条 vline 邻列、墙廊 14 列与门行、block0 邻域、四边 12 格。取 40–80 个分层源位置（每个配代表性端口），即可得到 ≥10⁹ 个精确标签，总成本 < 5 min、< 3 GB。
- 正反两向：对同一批位置再做反向图 Dijkstra（到该 pin 的距离场），让"作为目标"的一侧也被覆盖。
- 评估协议：全端点 × 全位置分层抽样（≥5M 行），公开 1M 仅作对照。

### 3.2 结构模型（S3）

```text
D = Lx(x0→x1) + Ly(y0→y1)        # 线路穿越前缀和（含超调 2c）
  + O(x0, sign, Δx)               # 超调/回退造成的额外穿越（分段常数）
  + W(...)                        # 墙 292·k / 绕门 dy 代价 + 落点平移
  + B(...)                        # block0 与四边断线导致的位移修正
  + M(s, t, Δ)                    # 位移度量（唯一需要表的部分）
```

`M` 的三级探索（S3 已用精确场测出能力上限，见 [`实验台账.md`](实验台账.md) §4）：

| 形态 | 实测 mae | 实测 acc | 体积/结论 |
|---|---:|---:|---|
| 斜率 + 余数（4 象限 × 120 余数） | 26–30 ps | — | 位移维不可用此形态 |
| 全局共享 pair 基 rank 128 | 10.15 ps | 97.82 | 复现旧路线水平 |
| 全局共享 pair 基 rank 256 | 9.42 ps | **97.96** | **撞墙**：加秩不再下降 |
| Tucker 64×64 | 7.22 ps | 98.44 | 246 MB，超预算 |
| **逐 cell 低秩 rank 32** | **2.16 ps** | **99.43** | 956 MB，不可直接装 |
| 逐 cell 低秩 rank 16 / 8 | 3.95 / 6.49 ps | 98.98 / 98.30 | 478 / 239 MB |

**S3 的核心发现（决定后续一切）**：延时矩阵在每个位移 cell 上只有 rank≈16–32，
但**端口对的模式随位移旋转**——任何共享基（含 Tucker）都在 ~9.4 ps ≈ 97.96 处撞墙，
这正是两条旧路线 98.1–98.2 上限的来源。因此 M 的表示必须是 **cell 自适应**：

| 级别 | 形式 | 预算 | 目标 mae |
|---|---|---|---|
| M1（对照） | 全局共享 pair 基 rank 256 | 31 MB | 9.4 ps（已知上限，仅作对照） |
| M2（主形态） | **cell 自适应分解**：`M(cell,s,t)=Σ_{a,b} A[s,a]·G[cell,a,b]·B[t,b]` 的逐 cell 核、或"基随 cell 平滑旋转"的低参数参数化、或 lane 级 `H(cell,j,k)`（160×160） | ≤ 40 MB | ≤ 5 ps |
| M3（兜底） | 近场（`|Δx|≤16, |Δy|≤20`）精确位移表 + 远场 M1/Tucker | ≤ 60 MB | 近场 →0，整体 ≤7 ps |

M2 候选实现路线（S3 已否证前两条朴素形态，见实验台账 §4.1）：
1. **组合签名聚类**（新首选）：旋转与位移的最优 hop 多重集/路线翻转绑定，而它可由 (dx,dy)
   用 O(1) 的硬币 DP 算出。按签名聚类后再共享基，并逐步把签名表做成解析式。
2. **lane 级 H(160×160)**：只对 `H(cell,j,k)` 做 cell 自适应分解，端点用 208×160 / 160×288
   精确表，查询时做 min-plus 归约（~17×17 次取 min）。
3. **结构化端口张量**：把 208×288 按端口结构（Z/I 的 方向×跨度×组×bit、逻辑 族×实例×bit）
   拆成低阶张量，逐 cell 只存少量系数。

已否证（勿重复）：模式聚类基（k=32,r=24 → 97.16，比全局基差）、位移 tile 共享基
（16 tile,r=24 → 97.54，与全局基同量级）。二者都说明旋转不平滑、也不离散成少数模式。

### 3.3 缺陷代数（S4，全部是公式不是表）

- **线路**：竖直/水平站点的穿越代价用前缀和 O(1)；判定 `lo ≤ site < hi`。
- **超调**：源端口首个 net 位移造成的往返，精确补偿 `2c`；墙廊列另加 132–248 ps 修正。
- **墙**：`x∈[76,89]`，`y∈[100k, 100k+49]`；水平穿越 +292；落点命中 block 时按"只数非 block 格"向后平移（可穿）；垂直不可穿，只能走 `y∈[100k+50, 100k+99]` 门廊。
- **block0**：`x∈[0,15]`、`y∈[0,99]` 无 SRB 且双向不可穿 ⇒ 绕行下界。
- **边界**：落点越界即断线；四边 12 格内的长 net 不可用 ⇒ 位移可用集修正。

### 3.4 运行时（S5）

- `mmap` 或大块读；端口名 → ID 用 64-bit 完美哈希（无字符串比较）；
- 输出复用大缓冲 + 自写整数格式化（不调用 `printf` 家族）；
- **批量 32–64 行预取流水线**：解析 → 算键 → prefetch 表行 → 计算 → 写回；输出顺序天然保持，不排序、不落临时文件。
- 目标：本机 1B ≤ 85 s（100M ≤ 8.5 s），官方按既有比例 1.17–1.40 预估 100–120 s。

### 3.5 选择性精确通道（唯一允许的线上搜索）

只有同时满足以下条件才允许上线，否则一律走结构式：

1. 实测单行 ≤ 1 µs；
2. 预期命中率 < 0.01%（总代价 < 10 s）；
3. 真值工厂证明该子类无法被结构式覆盖。

## 4. 评分换算与校准（摘要）

- 本机测速：容器内 `user + sys`，5 轮正反交错，100M 输入（公开 1M 请求重复 100 次），每轮校验输出哈希。
- 官方/本机比例：历史有 `1.16863`（pango 路线）与 `1.40179`（solution 路线）两个口径，**不可混用**。
- 本轮校准方式：用 100M 榜单（5 次/日）实测官方 100M CPU，×10 外推 1B，重算比例；1B 榜单（2 次/日）只在门槛通过后使用。
- 记分纪律：acc 与 CPU 必须来自同一个 ELF、同一资产、同一批基准，禁止跨批次拼接。

详见 [`评分换算与校准.md`](评分换算与校准.md)。

## 5. 阶段、门槛与停止条件

| 阶段 | 产出 | 通过门槛（未过不得进入下一阶段） |

├─ src/estimate.cpp             # 单线程流式实现

**接口契约**

- 调用：`bin/estimate -in <request.csv> -out <result.csv>`；
- 输入表头 `From,To`；输出表头 `From,To,delay`（小写，官方附件口径）；
- 保留输入端点和行序；同一引脚到自身输出 0；
- 接受 LF / CRLF / UTF-8 BOM / 文件尾无换行 / 空行；非法端口或字段数错误返回非零；
- 模型全部编译进 ELF，运行时不读外部文件；表头含魔数、版本、维度、量化尺度、SHA-256；
- 距离场格式：`uint16`，维度 `[208][60200][288]`，端口顺序与 SHA-256 写入索引文件；
- 本机 CPU = 容器内 `user + sys`；官方比例单列保存。

## 7. 风险、回退与纪律

| 风险 | 概率 | 应对 |
|---|---|---|
| min-plus 暂态无法紧凑编码到 5 ps | 中 | 回退 R1：M1 精确残差表（57.5 MB）+ 预取流水线；预期 acc 98.5–98.8、CPU ~100 s ⇒ 98.0–98.3 |
| 缓存缺失拖慢 CPU | 低 | 批量预取；I/O 地板 67 ns/行已实测 |
| 官方/本机比例漂移 | 中 | 早期用 100M 榜单实测官方 CPU×10 重算比例 |
| 榜单 2M 循环与隐藏 1B 分布不同 | 高 | 一律以真值工厂全端口/全位置抽样为主判据，榜单只作校准 |
| ZIP / 内存超限 | 低 | 模型预算 ≤ 40 MB；每阶段真实打包 + 独立容器运行 |

**纪律（防止重蹈旧路线）**

1. 模型选择只看真值留出；测试集冻结后只读一次；
2. 禁止用公开 1M 标签做最终选型；禁止跨批次拼接 acc 与 CPU；
3. 每阶段同时报 acc、mae、分桶、每行访存、表字节、ZIP、RSS、CPU；
4. 速度结论必须 5 轮交错 + 输出哈希；< 3% 的差异不作为路线依据；
5. 旧 `solution/` 产物只作基准对照（`estimate_stage11_balancedw64` 的 1M 逐行预测与 CPU），不作代码基础；
6. 任何"逐行精确"入口必须过 §3.5 预算闸门。
