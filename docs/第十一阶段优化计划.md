# 第十一阶段：基线匹配与分区相对误差压缩

本轮以本地 Docker 为准，不提交赛事远程平台。争取验证与测试回归准确度达到 98.25，相对同批第八阶段预计综合分优势达到约 0.2。最低默认发布门槛仍为两切片准确度不低于 98、综合分不低于同批第八阶段。未达目标时如实记录，不替换为退步候选。

## 推进顺序

1. 验证局部残差与旧基线、旧校准的匹配：当前配置、局部去除 M 修正、重新拟合校准、两者组合。新参数只用训练折，排除既定源位置留出与保留查询坐标；先看 valid，冻结后查看 test。区分固定分支代理与真实双分支结果。
2. 在相近在线成本和包体预算内比较互斥位移分区。短距分配更多表达能力，中距扩大覆盖；按生成距离构造相对误差权重，端口频率仅从训练几何统计。原始生成矩阵只读，不运行外部工程脚本。
3. 早期检查真实 C++ 精度、包体与 Docker 时间。冻结候选后重新匹配墙内模型，做百万行独立参考、保留精确查询、五轮同批测速、接口/边界/独立 ZIP 验收。必要时扩展 100M 测速，记录实际行数和外推倍率。
4. 联合门槛通过才更新默认；额外保留每轮 1B CPU 外推低于 1800 秒且准确度最高的版本。保留第十阶段两版及既有第七至九阶段备份，不覆盖旧模型、旧校准或历史证据。

## 判断依据与限制

简单增加全窗口秩在上一轮增加了精度但损失综合分，本轮优先改变压缩目标与容量分配。生成距离误差与最终公开标签误差分别记录，不把旧分支精确距离代理当成可部署上限。准确度增加 0.1 只允许额外约 0.096 秒/10M CPU，故精度与速度同时筛选。

历史公开切片反复使用，并非盲测；继承基线也不是全系统位置隔离。测速是重复公开输入的本地 CPU 外推，不是完整 1B 实测或官方成绩。按同批口径比较第八阶段，另保留历史绝对数值供参考。
