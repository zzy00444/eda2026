# 第十三阶段优化记录

更新于 2026-10-23。本轮以[官方时间对齐记录](stage11_official_benchmark_alignment.json)中的固定 CPU 比例 `1.4017890759604956` 估计时间分。总分公式为 `0.8 × 准确度 + 0.15 × 时间分 + 5`，时间分为 `100 × max(0, 1 − 校准后的 1B CPU 秒数 / 1800)`。准确度来自反复使用的公开测试切片，不能视为隐藏集成绩；本轮未远程提交。

## 结果

| 候选 | 测试准确度 | 本机 1B 外推 CPU | 校准 CPU | 校准估分 |
| --- | ---: | ---: | ---: | ---: |
| 同批默认 `stage11_balancedw64` | 98.192013 | 211.303420 s | 296.202826 s | 96.085253 |
| 独立候选 `stage12_b128` | 98.192013 | 194.273576 s | 272.330577 s | **96.284189** |

两版在五轮 100M 交错 Docker 测试中输出哈希一致。128 MB 分块相对同批默认版节省 17.029844 s/1B 本机 CPU，固定比例校准后估分增加 0.198935。历史默认版的基准为 200.458118 s/1B、校准估分 96.211944；本轮同批默认版较慢，说明单次校准比例和本机时序存在波动，跨批收益不能直接当成官方收益。`stage12_b128` 的 ZIP 为 98,094,793 B，进程峰值 RSS 约 660 MB，完成接口、边界和空目录独立 ZIP 检查。证据见[同批基准](stage13_b128_aligned_benchmark.json)、[校准估分](stage13_b128_aligned_score.json)、[准确度](stage12_b128_analysis.json)、[验收](stage12_b128_validation.json)、[包体](stage12_b128_package.json)。

候选尚未超过 97 分，故默认 `solution/submission.zip` 仍为已在官方平台测试的 `stage11_balancedw64`，最高精度 `stage11_compactw160_submission.zip` 继续额外保留。`solution/stage12_b128_submission.zip` 是可独立运行的速度候选。按当前 98.192013 的准确度，要达到 97 分，校准 CPU 需低于约 186.43 s，即本机 1B 外推低于约 133.00 s；在候选的 272.33 s 校准 CPU 下，准确度需约 99.09。仅调大分块不足以达到目标。

## 未采用的精度实验

新增[生成表残差拟合器](../solution/tools/displacement_generated_residual.py)，只读取外部工程已生成的 `all_C_<port>.bin`，用训练几何采样 8192 个位移列拟合 64 维残差，并导出稀疏 pair、lag-12 V 编码的 5,468,660 B 局部资产。架构表未修改，公开延时标签未参与拟合。部署候选 `stage13_gen64` 的验证/测试准确度仅 97.740186 / 97.733304，低于默认版，因此未打包或测 100M。见[拟合](stage13_gen64_fit.json)、[导出](stage13_gen64_local_export.json)、[准确度](stage13_gen64_analysis.json)。该全局低秩残差没有复现按位移分区模型的收益，下一轮不应继续盲目增加其秩。

## 冻结结论

用户已要求停止继续优化。本阶段到此冻结：不替换默认包，不进行新的远程提交，不再启动新的训练或长时间基准。当前应使用的资产如下：

- 默认提交：`solution/submission.zip`，仍为官方平台已测的 `stage11_balancedw64`。
- 最高准确度备选：`solution/stage11_compactw160_submission.zip`，公开测试准确度 98.247955。
- 当前校准估分最高的速度候选：`solution/stage12_b128_submission.zip`，同批校准估分 96.284189；它不是默认提交。
- `stage13_fastparse_fixed_submission.zip` 仅为修正解析路径的未长测诊断包，输出准确度与 `stage12_b128` 一致，不纳入发布选择。

## 后续恢复时的方向

优先研究短距离、小延时的相对误差损失，比较生成表直接距离与现有局部模型在真实查询分布上的差异。新的精度候选须先过公开验证、保留源位置和包体门槛，再做长时间 Docker 基准。速度方面，128 MB 分块已是本轮可复现收益，但还需要数量级更大的改进才能单靠时间达到 97 分。估分统一运行 `solution/tools/displacement_aligned_score.py <benchmark.json>`；报告应同时列出同批默认版，且不能把公开切片估分写成官方实际分数。
