# 第十阶段精度与综合分联合优化计划

更新：2026-10-21。状态：进行中。

本轮要求同时满足准确度不低于 98、预计综合分不低于第八阶段。仅使用本地 `fpga-ziguang:latest` Docker 测试，不向赛事远程平台提交。第八阶段备份、第九阶段默认版及额外保留的最高精度版全部保留；新方案通过联合验收后才切换默认版。

## 验收口径

- 准确度使用赛事相对误差评分，沿用固定 rng7 验证集、测试集。验证集选择配置，冻结后读取测试结果；这些历史切片已被多轮查看，不能称为盲测。
- 验证和测试准确度均须达到 98。对新增拟合参数，继续排除预留源坐标，并报告源坐标留出结果；继承的第八阶段参数仍有历史训练范围限制。
- 最终候选与保留的第八阶段 ELF 在同一批 Docker 中交替运行，各测五次 1000 万条。记录 CPU user+sys、输出一致性、内存、线程数；综合分采用测试准确度及十亿条外推 CPU 时间。
- 在 CPU 不超过 1800 秒的范围，预计综合分为 `0.8*accuracy+20-CPU_1B/120`。候选必须不低于同批第八阶段；同时报告相对历史第八阶段分数的结果。1000 万条外推不能冒充完整十亿条或官方成绩。
- 单线程、内存低于 2,000,000,000 字节、提交 ZIP 小于 100,000,000 字节。发布前执行接口、边界行为、独立 ZIP 及 Python/C++ 逐条一致性检查。

## 优先路线

1. **定位增益及成本。** 用既有基础预测、架构包络与第九阶段高精度预测分析验证集，识别主要误差区间；计算稀疏残差启用所需覆盖率。先判断能否把树模型的主要增益压入紧凑查表或少量算术。
2. **低成本残差。** 优先试验按包络差值、端口及几何特征索引的紧凑校正表、少量加性项或蒸馏。拟合仅使用训练部分，逐步记录验证收益；尽早编译并在 Docker 测量实际成本。
3. **联合调整基础表示。** 若残差成本仍超标，尝试减少基础低秩计算或直接利用架构表示，给必要的精度修正留出时间。保持各实验资产独立，避免覆盖已发布模型。
4. **冻结与验收。** 仅对验证精度和速度均有希望的方案读取测试结果，执行同批五次测速和发布检查。失败方案记录原因，不降低门槛，不用不同批次的时间拼接成功结论。

## 维护与停止条件

在诊断、可运行候选、最终结论等节点提交 Git；代码、记录、交接及重建说明同步更新，不推送远程。大数组、模型、ELF 和 ZIP 留在忽略目录，仅提交脚本、文档和紧凑证据。未达到联合门槛时，保留现有发布版本并明确说明差距。

持续优先验证能改变精度/速度关系的结构性改进；如多个独立的紧凑表示与加速方向均无收益，整理证据及下一步建议，避免只增加树数。
