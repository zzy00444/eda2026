# 第九阶段优化记录

第九阶段历史快照，记录于 2026-10-21；[当轮计划](第九阶段98分优化计划.md)已完成。当时默认切换为 `stage9_fast16`，另保留时间预算小于 30 分钟的高精度 `stage9_accurate64`。两者具名包及第八阶段速度包仍在，但 canonical 路径已由后续第十阶段接替，当前产物见[根 README](../README.md)。本页指标和发布操作保持第九阶段语境，最终指纹见本文末节和历史清单。

## 模型筛选

冻结第八阶段百万行预测，新增残差仅使用 719,583 条训练行；另外 180,375 条主训练行按源坐标哈希隔离，用于检查新增参数的位置迁移。继续排除上一轮三个保留坐标。第八阶段 M/校准曾使用主训练集，因此不将这组检查称为整个系统的新盲测。

训练使用 LightGBM 相对误差加权 L1，权重 `2000/max(truth,200)`；固定 rng7 验证集选型。普通几何、墙门、Net 落点/超调、端口族和基线预测的 160 树模型，验证 97.878654，新增参数留出位置 97.912229。添加前 32 个 U/V/UV 分量未改善，验证 97.876179，停止该方向。单棵 2047 叶树验证仅 97.745667。

周期架构四方向包络加源 Net Gap telescope 在验证集上没有超过真实值；直接下界截断使验证从 97.638770 提高到 97.723566，但不能保证所有隐藏请求。将包络及“基线−包络”作为两个特征后，127 叶、学习率 0.15 的验证曲线突破 98；选型报告见 [residual_selection.json](residual_selection.json)。1023 叶的少树模型没有优于 255 叶配置，未采用。

## 包络无损压缩

原周期表为 `4×208×120×288` 个 int16，共 57,507,840 B；直接压缩约 41.66 MB，无法放入本轮提交余量。对每方向的缩放势函数 `(a,b)`、相位 `(mx,my)`，表项满足 `T+a×mx+b×my` 能被 12 整除。

先精确除以 12，再改为 `[方向,源,目标,相位]` 布局，按相位作一阶差分。−127～127 用一字节，其他值用 `0x80+int16` 转义，最后 zlib6 压缩为 **17,424,731 B**。全部值往返核对通过，运行时还对重建的整表验证 CRC32，避免只测试少量查询。记录见[编码证据](stage9_bound_encoding.json)。原始压缩、混合差分与字节重排的对照见 [codec probe](residual_bound_codec_probe.json)。

模型表加载后按 `[源,目标,相位,方向]` 存放，相同请求的四方向项相邻，减少随机访存。压缩表追加在 ELF 主体后、原六段资产前；32 字节描述符为 `PGBND001 + uint64 offset,size,decoded_size`。原六段 footer 格式保持不变。C++ 使用评测镜像已有的 zlib，提交独立运行仍须验证。

## C++ 核对与性能修正

两个通用树遍历版本的 C++ 验证/测试成绩均与冻结 Python 相同。全量核对发现唯一差异为第 695621 行自环：C++ 按接口输出 0，导出参考误将包络 156 应用于该行。已修正 Python 参考的自环及 Net 落点资格处理，模型参数和非自环预测不变。

通用树表的首轮 10M CPU 为 16 树约 19.6 秒、64 树约 63.6 秒；后者的 1B 外推超过一小时，不能交付。两轮初筛保存在 [stage9_screen_benchmark.json](stage9_screen_benchmark.json)，其中二进制指纹对应被淘汰的通用遍历版本。现将同一冻结模型导出为直接 C++ 分支（导出命令增加 `--direct`），重新构建、核对输出和测时；不按测试标签重训。

直接分支版本已完成百万行与 Python 参考逐行核对，两个候选差异均为 0；直接分支前后输出字节也相同。验证/测试准确度与上表一致，修正自环参考后全公开准确度分别为 98.166670 / 98.173714。直接分支 ZIP 分别为 98,381,725 / 98,552,697 B，均低于 100,000,000 B。

新增参数位置隔离的准确度增益分别为 +0.361973 / +0.403344；按源坐标聚类的条件近似 95% 区间分别为 [0.348495, 0.375451] / [0.389408, 0.417280]。精确参考 48 条保留位置相对分：第八阶段 88.050655，16 树为 87.936545，64 树为 88.578985；因此不能声称所有位置均改善。该小集合也不能证明隐藏集达到 98。完整证据见 [stage9_generalization.json](stage9_generalization.json)。

用户进一步要求额外保留最高精度且不超过 30 分钟时间预算的版本。直接分支逐请求遍历的五轮证据见 [stage9_scalar_benchmark.json](stage9_scalar_benchmark.json)；64 树 10M 约 30 秒，当时不满足该预算。随后尝试 256 条请求一组、每棵树遍历整个小组以减少指令缓存切换，不改变树参数、每条请求的累加顺序和舍入规则。试验期间默认保持第八阶段，最终验收后才更新。

浮点特征的 256 行小批次将 64 树降至五轮均值 18.425739 秒/10M，仍略超预算；该实现的五轮证据见 [stage9_float_batch_benchmark.json](stage9_float_batch_benchmark.json)。最终特征全部来自整数坐标、端口、差分、整型基线和整型包络；将数值分裂 `f<=threshold` 等价改为整数 `f<=floor(threshold)`，叶值及累加仍为 double，并将小批次改为 128 行以适应一级数据缓存。导出器对全部训练格式特征核对有限、整数及 float32 精确可表示性；整数版两个候选的百万行输出均与原模型相同。导出命令增加 `--integer`。
