# FPGA 延时估算第四阶段结果

记录日期：2026-10-19。

本报告保留第四阶段历史结果，默认提交已由第五阶段替换。此处提升的是准确度；按官方总分考虑额外 CPU 扣分后，级联方案相对第三阶段没有总分净收益。见 `FPGA延时估算第五阶段结果.md`。

本阶段在第三阶段候选 `s3_topology_lr32_511l_25r` 上增加中距离残差级联模型，目标是在 30 分钟时间分界线内提高准确度。

## 最终候选

主模型仍为 `s3_topology_lr32_511l_25r`，使用 25 棵 LightGBM 树。查询距离小于 100 时执行完整 25 棵树；距离不小于 100 时先执行前 18 棵树。新增 `medium_cascade_127l_10r` 在 `100 <= Manhattan 距离 < 300` 时追加 10 棵小校正树，距离达到 300 时跳过校正。

校正模型训练目标是：

```text
真实延时 - 主模型前 18 棵树的预测值
```

训练只使用固定训练划分中距离位于 `[100, 300)` 的样本，使用 127 叶、学习率 0.15、10 轮、L1 残差目标。它没有改变短距离和长距离请求的主模型路径。

| 指标 | 第三阶段 | 第四阶段 |
| --- | ---: | ---: |
| 固定验证集准确度 | 96.0678948 | **96.0936254** |
| 固定测试集准确度 | 96.0528653 | **96.0784893** |
| 全公开集 C++/Python 不一致行数 | 0 | **0** |
| `100 <= distance < 300` 测试分 | 96.7738083 | **96.8225508** |
| 同引脚零延时 | 1/1 | **1/1** |

固定划分使用 `numpy.random.default_rng(7)` 的随机排列，验证集为 `[300000:350000]`，测试集为 `[350000:400000]`，其余 900,000 条用于训练。固定集是本地回归指标，不等同于官方隐藏集。

## 性能和稳定性

在 `fpga-ziguang:latest`、`--cpus=1 --memory=2g --memory-swap=2g`、PGO 编译条件下，对公开 100 万条查询重复 10 次得到：

| 轮次 | 10M CPU 秒 | 10M 墙钟秒 | 外推 1B CPU 分钟 |
| --- | ---: | ---: | ---: |
| 1 | 15.831966 | 16.086083 | 26.3866 |
| 2 | 15.992175 | 16.137331 | 26.6536 |

两轮输出 SHA256 均为 `2dd99f20695ef5156984682b6d43f5e52aa7a51121559f07bd33eb5ee254909a`。观察到的容器峰值内存为 897,855,040～900,055,040 字节，约 857～858 MiB；最大线程数为 1。完整记录见 `build/benchmark_cascade10_10m.json`。

没有运行完整 1B 条终测，26.39～26.65 分钟是 10M CPU 时间线性外推。正式机器、隐藏集和输入分布可能不同，应保留时间余量。

## 为什么采用级联校正

直接将主模型从 25 棵增加到 220 棵时，固定测试准确度达到 96.5227，但 1B 查询时间远超 1 小时。简单的距离专用模型替换会损失端口和拓扑交互信息；对 `[100,300)` 区间用小模型学习 18 棵主模型的残差，取得了准确度提升，但没有抵消额外 CPU 的总分损失。训练时对短距离样本加权、简单改用 `float`、模型蒸馏和仅保留大模型前 80 棵树均未超过该方案的准确度与时间约束组合。

## 产物和复现

- 默认可执行文件：`bin/estimate`，SHA256 为 `297991ea3852992902be1bf36a35e5809441291fae8d6d3785c7e3e9e86b17fa`。
- 默认提交包：`submission.zip`，大小 42,056,405 字节，SHA256 为 `c9fcd4c97298534e2fb6187d4c5e4f9c97ec6e2b81b70a5a3f77cc77b9673960`。
- 生成目录：`build/generated_s3_cascade10_pgo`。
- 全量核对：`build/cascade10_formal_metrics.json`。
- 训练脚本：`tools/train_cascade.py`。
- 导出脚本：`tools/export_cpp.py`，支持 `--cascade-model`、`--cascade-trees`、`--cascade-min-distance` 和 `--cascade-max-distance`。

复现顺序：先训练主模型，再运行 `tools/train_cascade.py`，然后用 `tools/export_cpp.py` 导出，最后在镜像内执行 `tools/build_candidate_wsl.sh ... pgo`。`tools/verify_cpp.py --all-rows` 应报告 0 行不一致。
