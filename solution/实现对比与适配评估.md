# `solution` 与 `pango_delay_handover_v3_lite` 对比及适配评估

记录日期：2026-10-19。

## 结论

两份实现解决的是同一个固定 SRB 架构问题，但模型表示、运行时数据和交付条件完全不同。当前 `solution` 已经有可在本机评测镜像中复现的源码、生成模型、Linux ELF 和提交包；`pango_delay_handover_v3_lite` 目录只有源码和部分中间文件，缺少其低秩模型表，不能直接在本机完成编译、运行和重新打包。

如果能从原计算机恢复 Pango 的五张模型表或完整 `submission.zip`，Pango 的 C++ 内核可以适配本机镜像重新编译。仅凭当前目录不能恢复模型：Pango 的 `Vt/U/M` 表格式与 `solution` 的 `architecture.bin/model.hpp` 不兼容，不能直接替换。

## 方法差异

| 项目 | `solution` | `pango_delay_handover_v3_lite` |
| --- | --- | --- |
| 基线 | 由 Arc、Net、Gap 生成的 4 方向周期架构代价表 | 端口对均值 `M` 与位移基 `V` 的低秩表示 |
| 误差模型 | LightGBM 残差树，主模型 25 棵；中距离追加 10 棵级联树 | rank-128 低秩点积，另加 gap telescope、wall/net-hop 修正 |
| 当前模型规模 | `architecture.bin` 约 57.5 MB，模型和表嵌入 ELF | `Vt/U/M/ids/arch` 约 99 MB，依赖打包脚本追加到 ELF 尾部 |
| 查询执行 | 单行流式解析、特征计算、树推理 | 16 MB 分块、按位移表行基数排序、AVX2/FMA 点积、完美哈希 |
| 当前本地结果 | 固定测试准确度 96.0785；10M CPU 15.8～16.0 s | 文档记载约 97.55；但当前目录没有模型表，无法独立复测 |
| 端点与输出 | 严格解析端口，输出 `From,To,delay` | 内核允许宽松跳过非法行，源码输出头为 `From,To,Delay`，需按正式附件改为小写 |

Pango 方案中最值得迁移的结构是源端口所属 Net 的远端落点修正：先计算“源引脚→Net 远端→目标”的两段 gap telescope，并对穿过 block 的候选加入 wall penalty。当前 `solution` 已计算 `first_dx/first_dy` 等特征，但没有把该结构项作为显式确定性基线；将其加入特征或基线后重新训练，可能带来收益，但必须在固定验证集和隐藏集约束下重新测量，不能直接把 Pango 的表拷贝过来。

## 本机适配检查

当前目录的阻断项如下：

1. `pango_delay_handover_v3_lite/build` 只有 `oracle_arch.txt` 和 `oracle_ids.txt` 等文件，缺少 `oracle_vt.bin`、`oracle_U.bin`、`oracle_M.bin`；`tools/build_linux.sh` 还引用不存在的 `vt32r96.bin`、`pu96_U.bin` 和 `pu96_M.bin`。
2. `tools/build_linux.sh` 将评测镜像查找路径写死为他人机器下的 `/mnt/c/Users/86151/Desktop/*/fpga-ziguang-latest`。本机镜像归档在 `F:\EDA\fpga-ziguang-latest.tar`，WSL 挂载路径为 `/mnt/f/EDA`，需要改为显式 `docker run` 或修改镜像路径探测。
3. 目录中的测试 ELF 在 Ubuntu-20.04 WSL 上需要 `GLIBC_2.34`，而本机 WSL 宿主环境的 glibc 较旧；必须在 `fpga-ziguang:latest` 容器内用 GCC 11.4 重新编译，不能直接运行他机 ELF。
4. Pango 的源码使用 `/proc/self/exe`、AVX2/FMA 运行时派发和 Linux 自包含表尾，适配到 Linux/amd64 评测镜像没有明显语言或 CPU 架构障碍；真正缺的是模型资产和可复现的生成输入。

因此，适配判定为：**源码层面可适配；当前交付目录不能直接适配验证；恢复模型资产后才可进行本机镜像重编和性能核验。**

## 建议顺序

1. 继续使用当前 `solution/submission.zip` 作为可交付候选，并在 Docker Desktop 恢复后按 `solution/README.md` 重编一次确认 ELF。
2. 若要验证 Pango，先恢复完整提交包或五张模型表，再改 `build_linux.sh` 的镜像路径、输出表头和模型文件名，最后在 `fpga-ziguang:latest` 内做 1K 接口、公开集准确度、10M 资源和 5 次一致性测试。
3. 若只追求 `solution` 提升，优先把 Pango 的 source-net 远端落点与 wall 修正转成可解释特征，训练一个小级联校正模型，再用固定测试集和 1B 时间外推共同筛选。
