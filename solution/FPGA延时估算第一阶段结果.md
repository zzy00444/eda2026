# FPGA 延时估算第一阶段结果

记录日期：2026-10-16。

本文是第一阶段历史快照；当前默认候选和现存产物见[项目 README](README.md)。2026-10-21 已清理旧二进制与运行缓存，文中的旧包和大文件路径不保证仍存在。

第一阶段目标是把公开数据固定留出集的准确度提高到 95 分以上，并形成可在 `fpga-ziguang:latest` 镜像中独立运行的 C++ 程序。目标已经达到：最终自适应 C++ 版本在固定测试集得到 **95.2761 分**，验证集得到 **95.2908 分**；C++ 与 Python 在两组留出样本上逐行一致。

## 实现

模型包含两层。第一层从 `SRB_Arc.json`、`SRB_Net.json` 和 Gap JSON 构造 10×12 周期的架构代价表，记录端口类型、方向和相对位移的预计算代价。第二层使用 600,000 条公开标签训练 75 棵 LightGBM 残差树，输入包括坐标、方向、距离余数、端口和端口族、长线首跳、Gap Line 以及 Block 区域特征。导出器把树变成 C++ 函数，把 57.5 MB 架构表作为 ELF 只读数据嵌入。

论文阅读带来的具体改动是 Map Lookahead 思路：按源线类型、方向和相对位移保存架构代价，而不是只用 Manhattan 距离；VTR 9 的局部 Lookahead 思路对应了端口进入和退出特征。论文讨论的是完整 FPGA 路由器，当前赛题程序只估算固定架构上的两点最短延时。

## 可复核指标

| 检查 | 结果 |
| --- | --- |
| 固定划分 | seed 7；训练 600k、验证 50k、测试 50k，三者互不重叠 |
| 最终 C++ 验证 / 测试 | 95.2908 / 95.2761 |
| Python 与 C++ 留出预测 | 0 行不一致 |
| 输入接口 | LF、CRLF、UTF-8 BOM、空行、无末尾换行均通过 |
| 零延时 | 同一引脚输出 0；公开零样本正确 |
| 五次输出 | SHA256 完全相同 |
| 10M 压测 | 25.07 CPU 秒；1 线程；约 41.5 MiB 进程峰值 RSS |
| 1B CPU 外推 | 约 41.8 分钟 |
| 提交包 | 仅 `bin/estimate`，41.8 MB，独立 ZIP 测试通过 |

公开的 8 条路径样例用于接口和格式检查，不用于训练。由于估算器优化的是大规模随机留出集，8 条路径的单独平均分为 87.29；这组样例数量太少，不能替代正式准确度指标。

## 主要文件

- `solution/src/main.cpp`：单线程流式 C++ 推理程序。
- `solution/bin/estimate`：在提供镜像内编译的最终 ELF。
- `solution/submission.zip`：可提交包。
- `solution/tools/experiment.py`：训练和评分。
- `solution/tools/architecture.py`：架构周期表生成。
- `solution/tools/export_cpp.py`：模型导出。
- `solution/build/final_metrics.json`：最终留出集逐行校验。
- `solution/build/benchmark_final.json`：五次 100 万条基准。
- `solution/build/benchmark_10m.json`：1,000 万条压力测试。
- `solution/build/manifest.json`：源码、数据和模型指纹。

## 下一阶段

正式评测的时间分仍有优化空间。当前版本 10 亿条外推约 41.8 分钟，下一阶段应针对树节点访问、端口字符串解析和输出写入做低风险优化，并单独提高距离小于 30 的请求分组准确度。所有改动继续使用固定留出集、容器单线程和 2 GB 内存限制复测。
